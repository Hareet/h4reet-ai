# Contract: the container specs

Plan §1 and §2 hold the design; this file is what the tests check (`deploy/night-shift/tests/test_containers.py`). contracts/runner.md §3 is how the runner turns a live spec into a `docker run` line, and what it refuses.

1. **Files**: `deploy/night-shift/containers/{supervisor,spec-writer,implementer,reviewer,red-teamer,ops,gate-runner,studio}.json`, plus the runner-only `plan.json` and `comfyui.json`. They are generated by `build.py` from `fragments.json`, and `build.py --check` exits non-zero when a committed file differs from what it would make. `build.py` also makes the three allowlists (`deploy/night-shift/allowlist{,-studio,-plan}.json`), so `--check` covers them too. Run it as `python3 -I -B deploy/night-shift/containers/build.py [--check] [--settings FILE]`. The install's fill step (G4) is `build.py --fill DIR --facts FILE --home PATH --tag SHA12`: it refuses unless `--check` would pass, then writes each committed spec, `x-h4` dropped and every placeholder filled, into `DIR/containers/`, and refuses the whole fill (exit 1) if a placeholder is left. By default it reads main's settings as `GIT_NO_REPLACE_OBJECTS=1 git cat-file blob refs/heads/main:.claude/settings.json`, for the night allowlist; `--settings` names a copy (the tests' fixture).
2. **Shape** (JSON), keys in this order:
   - `role`, and `parent`: the lattice parent, `ceiling`, or `runner` for the runner-only specs;
   - `image`: `h4-night-{worker,studio,comfyui}:{{IMAGE_TAG}}`, never `latest`;
   - `user` (`{{UID}}:{{GID}}`);
   - `mounts`: the role's own, each exactly `{"host", "container", "mode": "ro"|"rw"}`, parents before children (§4 lists what the runner adds);
   - `networks`;
   - `env`: names in capitals (`[A-Z_][A-Z0-9_]*`), and values; `CLAUDE_CODE_OAUTH_TOKEN` comes only through `env_file`;
   - `env_file`: the token file for sessions, and `null` for the runner-only specs. The runner passes the plan's credentials itself, and ComfyUI gets no token;
   - `cap_drop: ["ALL"]`, `security_opt: ["no-new-privileges"]`, `read_only` (true but for §7), `tmpfs`, and `limits` (`memory`, `cpus`, `pids`);
   - `gpus` (studio and comfyui only);
   - `requests`: the request kinds the runner takes from this role. These are `plan` for ops, `gate` for the gate runner, and `comfyui` for the studio. Each is off until its install turns it on;
   - `x-h4`: `{"example": true, "task": …}` in the repository. `task` names the runner's task mounts (§4), and the install drops `x-h4`.
3. **Never mounted, in any session container**, by a spec's mounts or the runner's:
   - `$HOME/.aws`, `$HOME/.ssh`, `$HOME/.config/h4reet-ai`, `$HOME/.config/gh`, `$HOME/.git-credentials`, `$HOME/.docker`;
   - `$HOME/.claude` and `$HOME/.claude.json`;
   - `/srv/studio/photos` and `/srv/studio/key`;
   - `/var/run/docker.sock` and `/run/docker.sock`;
   - `$HOME/.local/state/h4reet` and `$HOME/.local/state/h4reet-ai` (the engine's and the runner's state), and the provider mirror `$HOME/.local/share/h4reet/terraform-providers`;
   - every path outside the worktree that main's settings list in `sandbox.filesystem.denyRead` or `sandbox.credentials.files`;
   - the main checkout's working tree. No spec mount touches `{{REPO}}` at all, `.git` included: only the runner's task mounts reach `{{REPO}}/.git`;
   - and, but for the studio's, `/srv/studio/outputs` and `/srv/studio/workflows`.

   Nor is any ancestor of these mounted (`$HOME`, `/`, `/srv`, `/srv/studio`, `/var/run`, `/run`, and those of `{{REPO}}`). The runner-only specs keep the same rule for the secrets and the socket. The plan alone mounts `$HOME/.config/h4reet-ai/infra/` (§11).
4. **The runner's task mounts, and the masks** (contracts/runner.md §3). `x-h4.task` names them for the reader, and the tests count them as the role's:
   - `writing` (supervisor, spec-writer, implementer, ops): the worktree read-write, and `{{REPO}}/.git` **read-only**, with only the task's own parts of it read-write (FR-012). Those parts are `.git/objects`, `.git/worktrees/<task>`, `.git/refs/heads/night/<task>/`, and `.git/logs/refs/heads/night/<task>/`. No container mounts `.git` itself read-write: a session that could would change the repository's `commondir` and steer git outside the container (G1's review);
   - `reading` (reviewer, red-teamer, gate-runner): the worktree and `.git` read-only;
   - `none` (studio, comfyui): no worktree;
   - `plan`: its detached worktree, read-only, and `{{REPO}}/.git` read-only (the detached worktree's `.git` file points into `.git/worktrees/`; G2's integration review);
   - every session, besides: its role's Claude folder at `/night/claude` and its io folder at `/night/io`, read-write.

   The masks are read-only binds, which the runner adds only where a read-write mount would otherwise cover a protected path:
   - `.git/objects/info`, which holds the alternates, over the read-write `objects`;
   - the task's own `.git/worktrees/<task>/commondir`, over its read-write folder;
   - each worktree path that `GIT_NO_REPLACE_OBJECTS=1 git cat-file blob refs/heads/main:.claude/settings.json` lists in `sandbox.filesystem.denyWrite`, meaning each `./` entry but `./.git/…`, **that exists in the worktree**. The runner computes these at each start, so the masks follow main.

   A denied path a fresh worktree lacks isn't masked: docker would make a missing source as root, in the worktree. On main today those are `makefile`, `.mcp.json`, `.gitleaksignore`, `.github/workflows`, and `deploy/env` (G2's integration review). A session can create them on its branch, and with the index and objects writable it can also commit any content for a masked path without writing the file. The **merge-time refusal** covers both (contracts/runner.md §6). At every writing session's end, and before naming a stack, the runner lists what the branch changes since its merge base with `refs/heads/main`. It refuses each path that main's denyWrite names, that main's `.claude/hooks/protected-paths.sh` guards, or that lies under `deploy/night-shift/`. So the masks keep a session from writing a protected file in place, and the refusal keeps any change to one off a named stack.

   Everything else in `.git` stays read-only under the read-only `.git`, with no mask. That covers `hooks`, `config`, `info`, `packed-refs`, `HEAD`, `index`, `refs/heads/main`, `refs/tags` (a tag named main would shadow the branch), `refs/replace`, `commondir`, and the other tasks' folders and branches. The tests read main's settings the same way.

   What a spec must hold: no spec mount lies at or under a task mount's container path, or at `/`, `/etc`, `/usr`, `/bin`, `/sbin`, `/lib`, `/lib64`, `/proc`, `/sys`, `/dev`, `/night/claude`, `/night/io`, or `/night/settings*`. No spec mount touches `{{REPO}}`. So no spec can reopen a protected path: with every spec's mounts added, each stays read-only.
5. **Environment**:
   - no spec names `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`, `CLAUDE_CODE_OAUTH_TOKEN`, or any `AWS_` variable;
   - every session spec sets `HTTPS_PROXY=http://egress:3128` (the studio's: `egress-studio`), plus `SANDBOX_RUNTIME=1`, `DISABLE_AUTOUPDATER=1`, `DISABLE_TELEMETRY=1`, `DISABLE_ERROR_REPORTING=1`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, `CLAUDE_CONFIG_DIR=/night/claude`, and `HOME=/night/home` (a `tmpfs`), with caches under `/tmp`;
   - the engine roles (implementer, ops, red-teamer) set `DOCKER_HOST=tcp://127.0.0.1:2376`, `DOCKER_CONFIG=/night/engine` (the engine's client certificates, read-only), and `NIGHT_ENGINE_FWD=engine-fwd:2376`. The worker image's entrypoint forwards that port, so docker-relay takes its nesting path;
   - the repository roles turn off git's automatic gc and maintenance, and commit as `night-<role>` (`GIT_AUTHOR_*`, `GIT_COMMITTER_*`);
   - the studio reaches ComfyUI at `http://h4-night-comfyui:{{COMFYUI_PORT}}`, its container's name on `h4-night-studio`.
6. **Managed settings, settings layers, and images**:
   - every image carries `/etc/claude-code/managed-settings.json` with exactly `{"forceLoginMethod": "claudeai", "env": {"ANTHROPIC_API_KEY": "", "ANTHROPIC_AUTH_TOKEN": ""}}`, which the container probe's third run proved (research R-18). Each Dockerfile copies `deploy/night-shift/claude/managed-settings.json` there with `--chmod=0444`;
   - the role layers (`deploy/night-shift/claude/<role>.settings.json`) set the role's permissions, and none sets `apiKeyHelper` or an `env` key for a credential. The worker image holds the seven repository roles' layers at `/night/settings-<role>.json`, and the studio image holds the studio's there;
   - the session images (worker, studio, comfyui) hold a passwd entry for the Author's uid and gid, with the home `/night/home`, from build arguments the install takes from the facts file. The runner mounts nothing at `/etc`; the container probe mounted its own passwd instead;
   - the worker image's entrypoint runs the runner's command unchanged (`exec "$@"`), so `claude …` and engine-fwd's `socat …` run as given. When `NIGHT_ENGINE_FWD` is set, it first forwards `127.0.0.1:2376` to `engine-fwd:2376`;
   - `deploy/night-shift/images/pins.json` holds Claude Code's version, the bases by name and tag, and the devcontainer toolchain's arguments. It also holds Blender's URL and checksum (in two halves) and each image's context paths, which the install writes from `git show`. Each base reaches its Dockerfile only as a build argument, `image@digest`, and a base whose digest is `null` stops the install.
7. **GPU containers** (studio, comfyui): `--read-only` off, because the NVIDIA runtime's hook writes into the container at start (the probe's third run). Every other lock (user, `cap_drop`, `no-new-privileges`, internal network, limits) stays.
8. **Networks**: every spec's networks are internal:
   - `h4-night`, whose proxy is `egress`;
   - `h4-night-engine`, where only `engine-fwd` sits, joined by the engine roles alone, so another role has no route to it;
   - `h4-night-studio`, with `egress-studio` and `h4-night-comfyui`;
   - `h4-night-plan`, with `egress-plan`.

   The `egress*` and `engine-fwd` containers are the only ones also on the normal network `h4-night-out`.
9. **Lattice** (plan §2): for each edge, the child's mounts, the runner's task mounts included, are within the parent's, by host path and mode (`rw` covering `ro`). This is checked at every path either names, so a mask the parent has and the child lacks is a widening. Networks, requests, devices, capabilities, the read-only root, and limits are within the parent's too. The ceiling is computed as the union, not a file.
10. **Placeholders**: `{{UID}}`, `{{GID}}`, `{{HOME}}`, `{{REPO}}`, `{{NIGHT_ROOT}}`, `{{COMFYUI_DIR}}`, `{{COMFYUI_VENV}}`, `{{COMFYUI_PORT}}`, `{{BLENDER_DIR}}`, `{{ENGINE_CERTS}}` from the facts file, and `{{IMAGE_TAG}}`, the tag the install gives the images it builds (the reviewed SHA's first twelve characters). Any other `{{…}}` fails the build. No spec holds a runner token (`<task>`, `<worktree>`): the runner fills none in a spec.
11. **Off**: no session spec mounts the plan's values, its saved plans, its state, or the provider mirror; only `plan.json` does, and only the runner uses it. It mounts `$HOME/.config/h4reet-ai/infra` read-only, with `data`, `plans`, and `state` read-write (bootstrap's state is local).
12. **The example marker**: the runner refuses a spec file that has `x-h4`, or whose path isn't under `~/.config/h4reet-ai/night-shift/containers/`.
