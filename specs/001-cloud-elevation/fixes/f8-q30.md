## The cause

`scripts/infra/secrets_fill.py:220-230` (`fill`) treats a name the store lacks in one of two ways. If the name is in `OTHERS` (`:50-65`), it is reported as another writer's. Otherwise `source()` (`:172-187`) takes its value from the laptop's `prod.env` under the name's last part, or from `init_env.py`'s shapes, or, when neither has one, from the hidden prompt. `OTHERS` names `/h4reet/prod/ec2-instance-id`, but not `/h4reet/prod/ec2-autostart` (written by the account's root, `infra/account/handover.tf:38` on `impl-f7`) or `/h4reet/tunnel-end/HEALTH_CHECK_ID` (written by prod's root, `infra/prod/ssm.tf:21` on `impl-f7`). `impl-f7` adds both to `infra/parameters.txt` as `String`. If either were missing, the script would copy a laptop value or ask for one, and write a Terraform-owned `String` from outside Terraform.

## The design

- **The rule, and where it goes:** in `fill`'s loop, in the same branch as `OTHERS`, after the `present` check and before any copy, shape or prompt (before `source()` is called). A missing name is another writer's when it is in `OTHERS` or when its type on the list is `String`. One function, `writer(name, kind)`, returns that writer's text, or `None` for a name this target fills. `fill` calls nothing else for such a name, so `source()` never sees it. No value is read for it, none is generated, it gets no prompt and no `put-parameter`.
- **Its report line:**
  - present: `<name> present`, as for every name the store has (the morning check, `f8.md` step 3, still reads all present);
  - missing and in `OTHERS`: `<name> missing; <OTHERS' text>`, as today. `OTHERS`' own entries stay as each writer's text for the report (`make tunnel-keys writes it, …`, `make shared-state-tls writes it …`, `prod's apply writes it (Terraform)`, …), so a name with a known writer keeps its precise line;
  - missing, a `String`, and not in `OTHERS` (F7's `ec2-autostart` and `HEALTH_CHECK_ID`, or any `String` added later): `<name> missing; a String: Terraform's or a target's, never this target's (infra/parameters.txt's comment names its writer)`. `impl-f7`'s comment above its five names says which root or target makes each.
  - The summary's `<n> left to their writers` counts both kinds.
- **The exit code** when one is missing stays as for `OTHERS` today: such a name doesn't change it. 0 means nothing this target fills is left missing, even if a `String` or another `OTHERS` name is; 1 means refused, or a name it fills was not written; 2 means it couldn't run. A missing `String` is named on its line and in the summary's count. `make secrets-check` reports it too. Its writer (the apply, or the target) is the fix.
- **Every `SecureString` path stays as it is.** That includes the `SecureString` names in `OTHERS` (the tunnel's, the TLS key), the two renames in `LAPTOP_KEY`, `LAPTOP_FILE`, `SHAPE_AS`, the prompt, the 0600 files and "never `--overwrite`". The rule reads only the list's type column. The list has no `StringList` today, and `StringList` names are filled as before.
- **Not added to `OTHERS`:** F7's two names. The general rule covers them, which is Q30's answer over its "Others" (add only those two). The test below runs them through the rule, not through a table entry.
- **The docstring** says the same: "every `String` on the list" joins `OTHERS` among the names it leaves to their writers.
