## User Scenarios & Testing *(mandatory)*

### User Story 1 - The Author Applies One Proposal (Priority: P1)

As the Author, I want a single proposal and a patch, built so that I can read each new line beside the script line and the repository file it came from, and apply it in one commit.

**Why this priority**: it is the item. Everything else in this spec serves it.

**Independent Test**: `pytest scripts/corpus/test_film_claims.py` (plan §5), which checks the proposal's table: each corpus line has a source script line, and each script line is found verbatim in `films/`. Then, on a plain export with the patch applied, `corpus-check` says OK.

**Acceptance Scenarios**:

1. **Given** the proposal, **When** the Author reads a new corpus line, **Then** the proposal's table gives its script, its script line number, the file under it, and, where the films' note changed it after his approval, that mark.
2. **Given** the patch built from plain copies, **When** it is applied to a fresh `git archive` export of `main` with `patch -p1` (a `--dry-run` first), **Then** both are clean, `corpus-check` passes, and the pack, the resume's lock, the generated cases, and `content:check` are current.

---

### User Story 2 - A Visitor Gets Better Answers About How It's Built, Once He Opens It (Priority: P1)

As a visitor, I want the twin to answer questions about the kill switch, the cost meter, the data flows, the evals, local-first, the stack, and the lifecycle from what the project's own films say, and to say "I don't know yet" where the corpus doesn't.

`08`'s sections are read by free talk alone (no room topic in `config/room-topics.yaml` names it), and free talk is `ready: false` in `config/twin-readiness.yaml`. So no visitor reaches `08`'s new text until the Author opens free talk on his own evidence runs. But the new "Do not claim" lines are in the rules every topic's hash covers (`apps/web/build/twin-pack.ts`, line 17, `topicHashInput`, lines 220 to 228), so applying the patch also closes the three ready topics, mission, work projects, and hobbies and travel, until he re-runs his evaluations and re-marks them (Q141); spec 026's corpus patch closes the same three, and he applies the two back to back and evaluates once.

**Why this priority**: the reason for the item. The degraded side: a visitor's question the corpus doesn't hold still gets "I don't know yet".

**Independent Test**: the new Golden Q&A generate cases in the plain export (`npm run twin:pack -w apps/web`); `pytest evals/test_twin_readiness.py` and `vitest run apps/web/test/twin-pack.test.ts` pass; each new gap line generates a gap case.

**Acceptance Scenarios**:

1. **Given** a new Golden Q&A about the cost meter, **When** the case runs on the fake adapter, **Then** its `contains` terms are in the answer and its `not_contains` terms (every "Do not claim" line) are not.
2. **Given** a question about a result or a count the corpus leaves out (the latest pass rate, a run's cost, how many eval cases there are), **When** it is asked, **Then** the expected answer is "I don't know yet", from the gap line.

---

### User Story 3 - Nothing Unbuilt or Stale Becomes a Claim (Priority: P1)

As the Author, I want the twin never to state as built what is only planned, and never to state a number that moves.

**Independent Test**: the checker fails on a line that cites a "not built" script line, on a number outside a slot (in digits or in words), and on a currency amount (in digits or in words), and passes the exempt spans (FR-003).

**Acceptance Scenarios**:

1. **Given** the CPU-summary line and the pull-deploy line in `SCRIPTS.md`, **When** the checker runs on a proposal that includes them as claims, **Then** it fails; as rows in the left-out table, it passes.
2. **Given** "fifteen containers" in a proposed sentence outside a `{{slot:…}}`, **Then** the checker names the line and fails; given "ten cents", it fails as a currency amount.
3. **Given** a claim tag `[A 2026-11-06]`, a date, a repository path or URL, the Author's F3 words "up to 30 days" in quotation marks that R5 accepts, or a new Golden Q&A's leading `9.` (`9. *How does the kill switch stop spending?* — … [P]`, the numbered form `twin-pack.ts`'s `GOLDEN_ITEM` reads), **Then** the checker reads no number in it.
4. **Given** "metered to the millionth of a dollar" or "whole micro-dollars" in a proposed sentence, **Then** it fails as a currency amount in words.

### Edge Cases

- The Author overturns a clarification answer: the proposal is regenerated for that answer; the checker is unchanged.
- A script is edited after the proposal: the checker compares each cited script line verbatim and fails on a changed one, naming it.
- A line "about you" in a script that no corpus file holds: it stays out unless it is the Author's quoted words (Q6).
- A sentence that is a number word but no number ("one command", "one transaction"): "one" is not a number to G1 (`guards.ts`), so not to R4.
