Hareet calls it his agentic data layer: inside cht-agent, he built the CHT Docs and CHT Code Context MCP servers, and a custom-curated agent-memory of all CHT domains that keeps learning and updating. The documentation server is Kapa-backed: unified search over CHT documentation, GitHub issues, the forum, and source, as the Documentation Access Layer. The code-context server is OpenDeepWiki-based, with per-repo endpoints for cht-core, cht-conf, cht-watchdog, and cht-sync, and an LLM-generated wiki re-indexed weekly with a steering file, as the Code Context Layer. agent-memory is the file-based memory cht-agent learns into. Together with context engineering and best-practice tooling set up in a sandbox, this is what the agent needed to succeed.
