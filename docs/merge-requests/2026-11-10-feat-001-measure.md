### Where the build departs from the plan (plan.md §16)

1. **The architectures come from the engine's store through the Engine API, not `docker buildx imagetools inspect`.** imagetools asks the registry, so it can't run "offline against the seeded store". `GET /images/{name}/json?manifests=1` (Engine API 1.48) lists each platform the stored index names, including those whose content was never pulled. The docker CLI shows that view only in `docker image ls --tree`, which is experimental and has no machine-readable form, so the script speaks to the engine itself: over its unix socket, or over mutual TLS with the CLI's certificates.
2. **The load's rate is the gateway's global metered limit,** 60 a minute (`config/budgets.yaml`): the public cap's figures are P-6's, blank until group 8. The turns open the three ready pieces, as the room does; free talk isn't ready and answers 409 before the gateway. They come from one client, since edge drops the client label on the site's listener, so they go no faster than its caps allow over the run: 16 a minute for 30 minutes, under its 500 a day. Hello takes the other 44, over eight labels.
3. **The stub paid adapter is dev's synthetic adapter, inside dev's meters.** At $0.10 a call against the $2 fallback grant, it answers about 20 calls, and the run spends dev-cpu's grant for the day. The rest are degraded answers. Every request passes edge and the gateway, and the gateway reads the store's state for each one past the client caps. Only the stub's answers reach an adapter and write the meter's journal and ledger. The measurement exists to size EC2's memory for the stack as it serves, and on EC2 every admitted turn is a paid call until the meter's ceilings stop them. So a run with about 20 answers in 1,800 measures a stack that mostly isn't calling a model: the model call's span, Langfuse's generation through its worker into ClickHouse, and the ledger's rows carry about 1% of the load. The record and its table put that share beside the peaks, for you to accept or to ask for a longer answered window, which would need the dev-only clock or operator renewals inside the load.
4. **dev-cpu only.** prod is refused: with its model server stopped, its route would send the load to the paid fallback. Your repeat on the laptop isn't built. The run starts from the main working tree, whose files the engine binds (spec 000 contracts/env-files.md §7.3), and only after the checks: 30 GB free on C:, 16 GB of memory available, and no other agent session on the engine.
5. **The tunnel end's measurement moves to groups 5 and 8,** when its four services exist. Of today's images it runs the collector, which the inventory covers.
