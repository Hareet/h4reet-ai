### Where the build departs from the plan (plan.md updated in the same commit)

1. **No `python-hcl2`.** The gate's tools run under `python3 -I` with no third-party package, in your terminal before `terraform init`; `infra_policy.py` reads HCL with its own reader, which refuses (T0) what it can't read rather than guess. Group 3's `infra/test/` uses the same reader.
2. **The sandbox's denies take paths, not patterns.** `*.tfstate*`, `*.tfplan`, and `*.tfvars*` get `Read` and `Edit` denies; the sandbox keeps the folder that holds them, `~/.config/h4reet-ai/infra/`, under spec 000's deny. A pattern in `denyRead`, `denyWrite`, or `credentials.envVars` is unconfirmed, and a bad entry could stop every sandboxed command, so each env-var family is denied by its members' names.
3. **The compose policy's host rules move** to groups 5 and 7, as patches beside their P-I patches: no host class, `H4_HOST` key, or host env template exists yet to write or test them against.
4. **The gate runs no `terraform`.** Its `infra-check` step runs the policy over the export, as data; fmt and validate need your mirror and run in `make infra-check`, and your `make plan` runs init and plan.
5. **Spec 000's broader protected names stay** (`infra/*budget*`, `infra/*alert*`, `infra/*iam*`, `infra/*edge*`, `infra/*waf*`). They also hold `infra/lambdas/alert_bridge/` (group 4) and `infra/prod/edge.tf` (group 8), which would then arrive as your patches; narrowing them is a loosening, and yours to choose ("For the Author", 6).
6. **P-3 is shortened** to fit CLAUDE.md's 6 KB cap (`evals/agent-config/static.py`, FR-006): main's file leaves 170 bytes, and P-3 makes it 6143 of 6144.

### 4. The guard, the merge, and the park

The guard anchors on the tip the review reads: replace `REVIEWED_TIP` with the SHA in the Review section once T009 has run. It prints `guard: go`, and merges, only if the gate printed its merge line, your checkout is on `main`, the branch is at the SHA the gate checked, `main` and the reviewed tip are both ancestors of that SHA, and nothing changed since the reviewed tip but P-1's and P-3's files. Whatever it prints, it then parks your checkout off `main`:

```bash
b=feat/001-guards
log=~/gate-001g1.log
rv=REVIEWED_TIP
s=$(grep '^gate: ' "$log" | tail -n 1)
sha=$(printf '%s\n' "$s" | awk '{print $2}')
n=$(grep -c '^merge: ' "$log")
on=$(git symbolic-ref -q HEAD)
tip=$(git rev-parse --verify "refs/heads/$b")
mr=refs/heads/main
[ "$on.$tip" = "$mr.$sha" ] || n=0
ok=no
[ "$n" -gt 0 ] && ok=go
a=(merge-base --is-ancestor)
git "${a[@]}" "$mr" "$sha" || ok=no
git "${a[@]}" "$rv" "$sha" || ok=no
x='^(\.claude/|tools/gates/|CLAUDE\.md$'
x="$x|redteam/forbidden-actions\.sh$)"
c=$(git diff --name-only "$rv" "$sha")
k=$(printf '%s\n' "$c" | grep -Ecv "$x")
[ -n "$c" ] && [ "$k" = 0 ] || ok=no
echo "guard: $ok"
m="Merge $b (${sha:0:12})"
o=(--no-replace-objects merge --no-ff)
o+=(-m "$m" -m "$s")
[ "$ok" = go ] && git "${o[@]}" "$sha"
p=wip-park/11-10-2026
git --no-replace-objects switch -C "$p"
```

On `guard: no`, nothing merged: tell the session. If main moves after the review, the session merges it in again and the review's tip moves with it.
