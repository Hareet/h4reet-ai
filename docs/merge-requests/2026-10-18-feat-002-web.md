## Review

One pass by the reviewer agent, which didn't write the change, over both of this spec's implementation branches: **BLOCK, on one blocker, the same on both.** Its findings reached this session through the coordinator, and this section summarizes them. The review itself is the integrating session's.

**The blocker:**
- **What was wrong:** `main`'s policy was read as `main:<path>`, with `git show`. git resolves a bare `main` as `refs/main`, then `refs/tags/main`, then `refs/heads/main`, so a tag named `main` answers before the branch.
- **Why it mattered:** an agent session can create that tag. The tags directory under `.git/refs` is writable, and neither the command guard nor the reference-transaction hook refuses `git tag main`. A branch could have tagged its own approvals as `main`'s.

**Its fix (fc9fe49):**
- `web_image.py` reads each file as spec 003 reads its policy: `GIT_NO_REPLACE_OBJECTS=1 git cat-file blob refs/heads/main:<path>`. A missing blob counts as absent, so every content file is a draft.
- Two new tests hold it: a tag named `main` pointing at the branch changes nothing, and with no branch `main` a tag approves nothing.
- The documents now prescribe that read: the contracts (web-serving.md §1, resume-source.md §5), the plan (§1, §3), the data model (§4), research (R-08), tasks.md, and the workspace README.

**Two nits, fixed in the same commit:**
- edge's 503 page now sends `Referrer-Policy: no-referrer` and the site's `Permissions-Policy`, beside its CSP;
- `apps/web/package.json`'s description is ASCII. Its `§` was valid UTF-8, but showed as mojibake.

**What it found fine:** the coordinator's message named no other blocker on this branch. The review's own account of what holds is in the review.

**Its backlog, not fixed here:**
- **The gate grades `npm run build`** in the devcontainer, not the image's own build. Phase 2's content check reads that build's output, while what ships is the image's. The two run the same build with `main`'s policy, but the gate doesn't prove the image's output.
- **The gate's own reads of `main` by its bare name,** `main:GNUmakefile` and `merge-base main`, have the same weakness as the blocker. They're human-only code outside these branches: a fix for you, or for a later patch.
