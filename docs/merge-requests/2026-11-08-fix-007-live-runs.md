**3b. The guard, the merge, and the park.** It prints `guard: go`,
and merges, only if the gate printed its merge line, your checkout is
on `main`, the branch is at the SHA the gate checked, and `main` is an
ancestor of that SHA, so the merge writes the tree the gate checked.
After a merge it restarts prod on main. Whatever it prints, it then
parks your checkout off `main`:

```bash
b=fix/007-live-runs
log=~/gate-live.log
s=$(grep '^gate: ' "$log" | tail -n 1)
sha=$(printf '%s\n' "$s" | awk '{print $2}')
ok=go
grep -q '^merge: ' "$log" || ok=no
[ "$(git symbolic-ref -q HEAD)" = refs/heads/main ] || ok=no
[ "$(git rev-parse --verify "refs/heads/$b")" = "$sha" ] || ok=no
git merge-base --is-ancestor refs/heads/main "$sha" || ok=no
echo "guard: $ok"
m="Merge $b (${sha:0:12})"
o=(--no-replace-objects merge --no-ff -m "$m" -m "$s")
[ "$ok" = go ] && git "${o[@]}" "$sha" && make up ENV=prod
git switch -C wip-park/11-7-2026
```

On `guard: no`, nothing merged: tell the session, which moves the
branch onto `main` again if `main` has moved.
