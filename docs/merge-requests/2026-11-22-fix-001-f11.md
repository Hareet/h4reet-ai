## What changed and why

**F11, the tunnel end decides nothing from sshd's log** ([`specs/001-cloud-elevation/fixes/f11.md`](../../specs/001-cloud-elevation/fixes/f11.md)). F10's safety net ended the laptop's tunnel session when sshd's log held the whole line `channel_setup_fwd_listener_tcpip: cannot listen to port: 2201` (or 2202, 2203), and the tunnel end counted reconnections from `Accepted publickey for tunnel` anywhere in a line. Under `-e`, sshd 9.6p1 leaves a stranger's newlines and carriage returns as sent (only syslog's lines escape them), so a stranger on 2222, with no key, could write that line inside a failed KEXINIT's offer or a disconnect's description and end the laptop's session at will; and the accepted text, in an identification line or a user name, moved the count. Now server mode only scrubs and prints sshd's log: F10's net and the log-read count are gone, and F10's `tcp_retries2` 8 and sshd's client-alive stay. The tunnel end's `h4.tunnel.reconnects` counts new sessions holding the forwards, from the inode of the socket listening on 2201 in `/proc/net/tcp`, which only an authenticated session can change. The "Tunnel reconnects" panel's description and contracts/tunnel.md §7 say what each end counts. f10.md's claim that sshd escapes control characters is struck and corrected beside it, pointing to f11.md.

**No net in its place.** A silent dead session (the night of 2026-11-18) ends at the kernel's bound: `tcp_retries2` 8 gives up 102 to 204 s after the first unanswered packet, about two minutes for a home link, about as long as a hard-restarted laptop takes to come back. A net that decides from state alone was weighed and isn't built: which process holds the forwards is only named in `/proc/<pid>/fd`, which sshd may hide from its own user; "a newer authenticated session exists" can't be read from state (a refused session lives under a second, and the admin-only client is a newer authenticated session that wants no remote forward); and "its connection is retransmitting" is a second `tcp_retries2` with a threshold to pick. It would buy a minute or two in a rare case. f11.md has the whole weighing.

**The count kept, from state, not dropped:** the laptop's own count reaches only the laptop's collector, so on EC2's dashboard the tunnel end's series is the tunnel's only one.
