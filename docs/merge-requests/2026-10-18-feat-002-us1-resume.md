## What changed and why

FR-013: "THE SYSTEM SHALL render the interactive resume and the PDF from one resume source, drawn from the corpus and its filled facts slots, so that WHEN either is built, the two hold the same claims in the same words (W3), apart from the header, as FR-017 says." This branch builds that source, its check against the corpus, both renderings, and the first draft, and publishes nothing of it until you approve its hash.

1. **The source and its check (T026):** `apps/web/build/content.ts`.
   - It parses `apps/web/content/resume.yaml` with the `yaml` package's core schema, refuses aliases and any field the contract doesn't name, and holds IDs, lengths, verbs, and slot references to data-model.md §2.
   - It runs C1–C9 on the room's header and every item, on every build, published or withheld, and fails the build at each item's first problem, as `<item-id>: <reason>`. A private denylist phrase is reported by its line, never its words.
   - The forbidden list (C9) is shared with narration's N3: each corpus file's "Do not claim" key phrases, the surname rule (each word of `main`'s `full_name` after the first), and the private denylist when the checkout can read it.
   - Slots fill from `corpus/facts/*.yaml`: a filled, public-safe value's phrasing, else the fallback, else nothing.
2. **The lock (T023, T031):** `apps/web/content/resume.lock.json`, the SHA-256 of the five corpus and facts files the draft reads, written by `npm run content:lock -w apps/web` (which refuses while C1–C9 fail). `test/content/source.test.ts` checks the committed source and its lock, so `make test` and the gate fail when a cited file changes, naming it (FR-016). The build only warns on a stale lock, so a slot you fill on `main` never stops `make up`. `npm run content:check -w apps/web` runs both from the command line.
3. **What the build publishes:** the resume's part of `dist/room-data.json`, through a new `parts` option on `approvals.ts`'s `roomDataFile`:
   - **approved:** the header and items, each with its source file and that file's SHA-256, and `published` naming the file;
   - **draft, with `ROOM_DRAFTS=1`** (dev's and dev-cpu's images): the same under "Draft, not approved", `published` marking it `draft: true`;
   - **withheld, without drafts** (prod, the gate, `make check`): no header and no items, and a PDF whose only text is "Draft, not approved". `test/smoke.test.ts` checks that no built file holds a withheld draft's words.
4. **The PDF (T027):** `apps/web/build/pdf.ts`, with PDFKit, from the same rendered items in the same order:
   - Tagged: a `Document` with `H1` (the name), a `P` per header line, then `H2` and an `L` of `LI` (`Lbl`, `LBody`) per section. `MarkInfo/Marked`, `StructTreeRoot`, `Lang (en-US)`, and `DisplayDocTitle` on the catalog.
   - `Info` holds `Title` ("Resume") and `Author` (the name the header shows) only. PDFKit's `Producer`, `Creator`, and `CreationDate` are taken out before it writes them, and its XMP stream, which it writes for every version above 1.3, is suppressed. The file ID is PDFKit's hash of the info with a fixed date, so the same source and policy build the same bytes.
   - The header follows FR-017 from the policy directory's `resume-header.json`: with both slots filled, the full name, the contact, then the room's header lines; otherwise the room's header.
   - Letter size; the draft fits one page (rendered to an image with pdf.js and looked at during the work).
   - **Its text beside it, `resume.pdf.txt`:** the PDF's text as pdf.js reads it through the embedded font's ToUnicode map, a line broken after a hyphen rejoined. The font stores glyph codes, so the gate's scan of `dist/` can't read the PDF itself; with this file, **the content check covers the PDF**. Verified with the approvals patch's `content_check.py` (below).
5. **The font (T028):** `apps/web/fonts/`, IBM Plex Sans Regular and Bold, under the SIL Open Font License 1.1 with IBM's Reserved Font Name "Plex", `LICENSE.txt` beside them.
   - **From:** the npm registry's `@ibm/plex-sans` 1.1.0 (2024-11-11, the newest; IBM publishes Plex there from its `ibm/plex` repository), `https://registry.npmjs.org/@ibm/plex-sans/-/plex-sans-1.1.0.tgz`. The tarball matched the registry's `sha512` integrity before anything was taken from it; GitHub, the other upstream, is outside the sandbox's network. The package was never installed, so its install script, an IBM telemetry hook, never ran.
   - **Pinned:** `fonts.lock` records the tarball's URL, SHA-256, and integrity, and each file's SHA-256 and path in it, all computed by a script. `loadFonts` refuses a font whose bytes differ, and `test/fonts.test.ts` checks every file.
   - **WOFF, not WOFF2:** fontkit, PDFKit's font library, fails to subset Plex's WOFF2 (its composite glyphs), and browsers read WOFF, so the same two files serve `src/fonts.css` and the PDF. The license's line endings are LF, as `.gitattributes` stores text; the lock notes it.
6. **The interactive resume (T029):** `apps/web/src/resume/`, a panel with the header, each section's heading, and each item as a `<button>` in a list, "Download (PDF)" to `./resume.pdf`, and "Close". Any control marked `data-resume-open` opens it, and "Close" or Escape closes it, focus back on that control. Selecting an item marks it (`aria-current`) and dispatches `room:item-selected` with its ID; opening dispatches `room:resume-opened`, for Phases 5 and 6. Until Phase 4's room exists, the first screen has a "Read the resume" button. The first screen's "Download the resume (PDF)" link is plain HTML, so it works with no script and no room (FR-018).
7. **The first draft (T030):** `apps/web/content/resume.yaml`, a header ("Hareet", the role, the SRE background) and 15 items in four sections, from the corpus's "Role at a glance" and topic sections. Every item cites the sentences it rests on, under sufficient tags; no item states a number; five existing slots, all unfilled, render nothing yet. Filed for you as `corpus/proposals/resume-2026-10-18.md`, with each item's words beside the corpus words it cites, three slots the years would need (unfilled, for you to add if you want them), and what the draft leaves out and why.
8. **The npm pins**, exact, from the registry, each the newest stable release published at least two weeks before 2026-10-18. All are development dependencies; the image holds only `dist/`.

## Backlog

- **The PDF's text file is the build's own.** `content_check.py` reads `resume.pdf.txt`, which agent-editable code writes; a build that shipped a draft's PDF beside an innocent text file would pass, as the last verification shows. The check could read the PDF itself: PDFKit's output is simple (Flate streams, one ToUnicode map per font), so a stdlib extractor in the human-only check is a page or two of Python. Yours to decide; it touches `tools/gates/`.
- **The private denylist never meets `resume.yaml` itself.** C9's private part runs only where the checkout can read `corpus/intake/private/`: never in an agent session, and never in the gate's container, whose export leaves it out. The gate's `corpus` step covers the proposal's copy of the draft's words; a later edit to `resume.yaml` without a proposal would reach the denylist only at `make publish-check`. The gate's `corpus` step could scan `apps/web/content/` too (human-only).
- **C8 is a word match:** a verb the text uses in another role ("which others built") satisfies it. C9's "Do not claim" phrases and your read are the guard.
- **A corpus edit on `main` that removes a sentence a citation quotes** fails the web image's build (C2), so `make up` stops at `web_image.py` until the draft or the corpus changes. The gate catches it on a branch; a direct corpus edit on `main` is the case.
- **`built_from` has no commit:** the image's build has no git, so `web_image.py` would have to pass one.
- **Vite's warning** that its native config loader would refuse extensionless imports in `vite.config.ts` and `build/` lists the new modules beside the old ones; it's the workspace's existing pattern, and nothing fails.
- **Line breaks after hyphens** in the PDF ("cht-pr-" / "review"): the text file rejoins them; a reader shows them as they are.
- **No XMP stream,** as the contract asks: a PDF/UA validator will report the missing `pdfuaid` identification. Quickstart §3's screen-reader check is the accessibility proof.
- **Two weights of one font:** "one open-licensed font" read as one typeface, Regular for the text and Bold for the name, the headings, and the draft notice.
