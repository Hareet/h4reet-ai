## Decision

1. **No usage event, no span, no panel for three behaviours.** The dinosaur's eating (spec 024), the twin's and the dog's run from the dinosaur (spec 025), and the twin's petting of the dog (spec 026) send no usage event, open no request, write no span, and add no dashboard panel or count. `EVENT_KINDS`, `config/room-events.yaml`, and row V4 stay as they are for them; row V4's "Never carries" keeps "avatar" in its words. **Spec 028's two cases, the same way** (this amendment): the dinosaur's scene (FR-019 to FR-026) and a dog visit's introduction (FR-027) send no usage event, write no span, and add no panel ("Telemetry span: none; the scene and the introduction are a named deviation (Assumptions)", spec 028, `spec.md:319`).
2. **It is a deviation, and permanent for these three features and spec 028's two cases.** For spec 028's two cases, "permanent" is not spec 028's word (its Assumptions name the deviation and leave it to this ADR); it rests on the page of 2026-11-15's Q21 (doc-028's: "Does ADR 0055 take spec 028's two cases, the dinosaur's scene and a dog visit's introduction, under its reason …?"), its recommended answer taken provisionally under his rule 1, no `Answered:` line yet (added by `docfix-028`, rv-doc-028's finding 4). Principle II's "telemetry that makes it observable in production" and Development Workflow 7's "A feature without a graph is not done" are not met for these behaviours. Each spec carries the written justification the governance asks for (024's A5, 025's "Deviations named", 026's "Deviation named", 028's "Deviations named"); this ADR is the governance's "ADR if permanent". No accepted ADR is reversed (each spec's words: "No accepted ADR is reversed"). Development Workflow 5's CI list (`.specify/memory/constitution.md:66`) holds "telemetry present for new paths", which none of the three specs names; this ADR reads "paths" as request paths, and none of the three adds one (spec 024's FR-014, "add no request"; spec 025's FR-027, "no network request"; spec 026, "the petting sends nothing (FR-025)"; spec 028, "No new row and no new destination" (`spec.md:315`; the room's dog's files the scene fetches are static files row V1 already lists, FR-030), and for the introduction FR-027's "It SHALL NOT … call the gateway, or send anything"), so it isn't a third deviated clause. That reading is Q305 on the page of 2026-11-14 (adr-nousage's), its recommended answer taken provisionally.

## Consequences

- In production, nobody can see how often a visitor eats, runs the twin and the dog off, or sees the petting, or whether any of these misbehaves short of a failed model file. A failure that doesn't fail a file shows only in the visitor's console (spec 024's one `console.warn`) or in a draft build's frame log (specs 025 and 026), neither of which leaves the device. These behaviours are proved by their tests, not by production telemetry.
- The same for spec 028's two cases: nobody can see in production how often the dinosaur's scene plays or is cut, or how often a dog visit's introduction shows.
